# Quark Drive

[Quark Drive](https://pan.quark.cn/) (夸克网盘) is a Chinese consumer
cloud storage service by Quark. It stores files under the `quark` alias.

Paths are specified as `remote:path`.

Paths may be as deep as required, e.g. `remote:directory/subdirectory`.

## Configuration

Here is an example of how to make a remote called `remote`.  First run:

```console
rclone config
```

This will guide you through an interactive setup process:

```text
n) New remote
r) Rename remote
c) Copy remote
s) Set configuration password
q) Quit config
n/r/c/s/q> n
name> remote
Option Storage.
Type of storage to configure.
Choose a number from below, or type in your own value.
...
XX / Quark Drive
   \ "quark"
Storage> quark
Option cookie.
The cookie used to log in, from your Quark account. It is rotated by rclone
automatically when the API returns a new value.
Enter a string value. Press Enter for the default ("").
cookie> <your cookies>
Option root_folder_id.
ID of the root folder. Blank means the default "My Drive" folder id 0.
Enter a string value. Press Enter for the default ("0").
root_folder_id>
```

The `cookie` is copied from your browser after logging in to
[pan.quark.cn](https://pan.quark.cn/). The useful part is a string like
`__pus=...;` or `__puus=...` from the `Cookie` request header. Password
managers cannot fill this in for you, it is best stored via
[`rclone config password`](/commands/rclone_config_password/) or the
environment variable.

Because the cookie expires, rclone rotates it automatically: whenever the
API issues a new cookie value, it is written back into the config file.

You can also set the cookie with a connection string, e.g.

```console
rclone lsd :quark,cookie='__pus=xxx;':
```

## Uploads

Files are uploaded to Quark in parts straight to the Alibaba Object
Storage Service (OSS) endpoint provided by the pre-upload call. The
upload progress shown by rclone therefore reflects the real upload, not
a buffering stage: uploading a large file shows the percentage of bytes
actually written to Quark.

Uploads do not send a file hash when the source cannot provide one. When
the source can give both MD5 and SHA-1 without the backend reading the
stream (most remote backends expose them in their metadata), the backend
asks Quark up front whether it already has the content: a hit creates the
file instantly - Quark's 秒传 deduplication - and skips the transfer
entirely, in both the single-stream and the multi-thread copy paths (the
chunk writer reports the object already exists and rclone does not even
read the source), so a 3 GB file that already exists in Quark is neither
re-uploaded nor re-downloaded from a remote source. A miss (or a hash-less
source) uploads as described above. rclone also avoids re-copying files
that already exist with the same size when a validation method is in use.

## Downloads

Downloads of large files are read as a chain of small ranged requests
(the default rclone multithread cutoff applies, see `--multi-thread-cutoff`).
All ranges of a file share one signed download URL, which the backend
re-signs only when it expires. This matters for throughput: quark serves
short ranges from a used URL at full speed, while throttling long
single-stream transfers to roughly 100 KiB/s.

Download ranges are sent over HTTP/1.1, matching the OpenList client. The
API and upload traffic stays on HTTP/2. quark's download edge resets long
HTTP/2 streams, and Go would multiplex concurrent multithread streams onto
a single HTTP/2 connection, collapsing them into one throttle bucket and
capping the whole transfer at roughly 1.4 MiB/s regardless of
`--multi-thread-streams`. One HTTP/1.1 connection per stream keeps each
stream in its own bucket, restoring per-connection speed.

## Modification times

Quark has no API to set a file's modification time; the timestamps you
see on files are assigned by the server and may differ from the source.
Because of this the backend reports that modification times are not
supported, and comparisons between Quark and other remotes are made by
size. Use `--size-only` when correctness of the timestamps matters less
than avoiding re-copies, e.g.

```console
rclone copy /local/path remote:path --size-only
```

Note that a file whose content changed without changing its size is not
detected as changed by a size-based comparison.

### Standard options

Here are the Standard options specific to quark (Quark Drive).

#### --quark-cookie

The cookie used to log in, from your Quark account. It is rotated by rclone automatically when the API returns a new value.

Properties:

- Config:      cookie
- Env Var:     RCLONE_QUARK_COOKIE
- Type:        string
- Required:    true

#### --quark-root-folder-id

ID of the root folder. Blank means the default "My Drive" folder id 0.

Properties:

- Config:      root_folder_id
- Env Var:     RCLONE_QUARK_ROOT_FOLDER_ID
- Type:        string
- Default:     "0"

#### --quark-encoding

The encoding for the backend. See the encoding section of the docs for more info.

Properties:

- Config:      encoding
- Env Var:     RCLONE_QUARK_ENCODING
- Type:        Encoding
- Default:     Slash,Del,Ctl,InvalidUtf8,Dot
